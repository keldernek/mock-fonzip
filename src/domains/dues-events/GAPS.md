# dues-events gaps

Spec gaps found while implementing the dues-events operations. Use the tables in `../../../PARITY.md` as the format: the spec location, the problem, and what the mock does. Give each waiver in `parity-waivers.json` next to this file a matching row here.

## Membership dues and debts

Dues and debts share one ledger, the `subscriptions` collection. The record's `status` tells them apart: 1, 6 and 8 are debts, and 2, 3, 4 and 7 are payments, cancellations, refunds and balance fixes.

| Spec location | Problem | Mock behavior |
| ------------- | ------- | ------------- |
| `paths./subscription/{subscription_id}` and `paths./debt/{debt_id}` | Both return `MembershipDueDetails`, and the spec does not say which records each serves. | `/subscription/{subscription_id}` serves every ledger record, debts included, because the member's statement (`/user/{user_id}/subscriptions`) lists debts as membership dues. `GET`, `PUT`, `PATCH` and `DELETE /debt/{debt_id}` serve only debts (status 1, 6 or 8) and answer 404 `Debt not found` for any other record. |
| `MembershipDueDetails.status_name` | The names are not documented. | 1 `Ödenmemiş Borç`, 2 `Ödeme`, 3 `İptal`, 4 `İade`, 6 `Silinmiş Borç`, 7 `Bakiye Düzeltme`, 8 `Ödenmiş Borç`. |
| `MembershipDueDetails.balance` and `UsersMembershipDues.balance` ("Balance at operation") | How the balance is computed is not documented. | A running sum over the member's records in operation-date order, ties by id. Debts with status 1 and 8 subtract their amount. Payments (2) add theirs unless the transaction failed or never completed. Refunds (4) subtract. Statuses 3, 6 and 7 leave it unchanged. Every write recomputes the member's running balances. Recomputing the seed this way changes none of its 426 balances. |
| `paths./subscriptions.get` query `status` | The spec does not say which records `paid`, `refund` and `failed` select. | `paid`: payments (2) whose transaction succeeded (`payment_status` 3). `refund`: refund records (4). `failed`: payments whose transaction failed (5). A refunded payment appears only through its refund record. Records with no transaction (3 and 7) are never listed. |
| `paths./subscriptions.get` and `paths./debts.get` query `query` | The fields searched are not documented. | The member's name, first and last name, email, phone, TC kimlik number and the record's details. Matching ignores case under the Turkish locale, and a leading `-` excludes matches, as `components.parameters.Query` documents. |
| `paths./subscriptions.get` and `paths./debts.get` query `create_date` with `create_date_cnd` null, and `paths./debts.get` query `operation_date` | The meaning of a null condition on a date is not documented. | Null means the same calendar day in Istanbul. `<` and `>` compare instants strictly. |
| `components.parameters.BinNumber` and `components.parameters.LastFour` | Typed as integers, but the card digits are strings. | Compared as numbers, so `last_four=123` matches `0123`. |
| `added_by__name` on `GET /subscriptions` and `GET /debts` | "Case-insensitive, unaccented", but not whether it matches the whole name. | Matches part of the name, ignoring case and Turkish accents. |
| `paths./user/{user_id}/subscriptions.get` | The order and the meaning of `listing` (`a`, `p`, `d`, `r`) are not documented beyond their names. | Newest operation first, newer record first on ties. No `listing` means `a`. `p` lists payments (2), `d` debts (1, 6, 8), `r` refunds (4). Cancellations (3) and balance fixes (7) appear only under `a`. |
| `paths./debts.get` start_date, end_date, create_start_date, create_end_date | The descriptions accept a bare `YYYY-MM-DD`, but each schema says `format: date-time`, so the pipeline refused bare dates. | `Shared:` normalization in `src/spec/normalize.ts` lets these four parameters match either format. A bare start is the start of that day in Istanbul. A bare end covers the whole day. A pair sent alone gets 400 `start_date and end_date must be sent together`. A start that is not before the end gets 400. |
| `DebtCategoryListItem.listed_count` ("Debts of active members, which `/debts` lists") | "Active member" is not defined. | A member who still exists. `GET /debts` leaves out the debts of a deleted user, and `listed_count` counts debts of every state of existing members. |
| `paths./debts.get` query `possible_duplicate` and `no_debt_category` | Only `true` is described. | `false` applies no filter, like leaving the parameter out. Duplicates are counted across every debt of the association, whatever its state. |
| `paths./debt.post` (createDebt) and `CreateDebt.add_payment` | When a debt becomes paid (status 8) is not documented. | Recording a payment settles the member's open debts oldest first. The credit is successful payments less refunds and paid debts, and a debt is settled only when the credit covers it fully. The payment's `assignment_status` becomes 2 (paid and assigned) when it settles a debt, otherwise 1 (paid, not assigned). Refunding or deleting a payment does not reopen the debts it paid. The seed already holds paid debts whose payment was refunded. |
| `components.requestBodies.CreateDebt` | No field is required. | `user_id` is required (400), and an unknown member gets 404. With `amount_type: custom` (the default), `amount` must be above 0 (400). `operation_date` defaults to now. `period` defaults to the operation date's day. `due_date` defaults to the operation date. `details` defaults to empty and `bill_no` to none. A recurring debt with a `recurring_period` gets `recurring_amount` equal to its amount and `recurring_next_cycle` that many days after the operation date. |
| `CreateDebt.amount_udv_key` | Whether the key is the field key (`mezuniyet_yili`) or the UDV key (`udv_11`) is not documented. | The field key, the `value` that keys `user_defined_values`. A missing key gets 400, an unknown key 404 `User defined value not found`, and a member value that is not a number above 0 gets 400. |
| `CreateDebt.add_payment` | Which payment fields are required is not documented. | `payment_method` is required (400), and 0 (card) or `payment_method_select: card` gets 400 `Card payments cannot be taken through the API`. `custom_amount` is required (400). `custom` needs `amount` above 0. A `bank_account_id` the organisation does not own gets 404 before anything is written. |
| `CreateDebt.send_mail` and `thanks_mail_id` | No documented endpoint shows a sent dues mail. | The template is checked: `send_mail` without `thanks_mail_id` gets 400, and an unknown template gets 404 before anything is written. No mail is recorded. |
| `components.responses.CreateDebtSuccess` property `currency` | The format of "The payment's currency" is not documented. | The ISO code. Payments recorded through the API are in TRY. |
| `CreateDebt`, `UpdateDebt` and `UpdateDebtStatus` | Who is recorded as the author is not documented. | Records written through the API carry no admin. `added_by_id` and `updated_by_id` are null, as `DebtCategoryListItem.created_by_id` documents for API-created categories. |
| `components.requestBodies.UpdateDebt` ("send them all") | Which fields are required, and what happens to fields left out, is not spelled out. | `period`, `operation_date`, `due_date` and `transaction.amount` are required (400). A left-out `details` becomes empty, `bill_no` and `remove_note` are cleared, and `recurring_period` becomes 0. `remove_note` is kept only on a removed debt. `transaction.transaction_id` and `transaction.payment_method` are ignored, because a debt carries no transaction: the payment that pays it does. |
| `UpdateDebt.debt_category_id` ("the debt's current one is accepted even if it was deleted since") | A category's debts move before it is deleted, so a debt can keep a deleted category only after a move fails part way. | The rule is implemented. Moves cannot fail part way in the mock, so only a test that edits the store can reach this state. |
| `components.requestBodies.UpdateDebtStatus` | The transitions are named but not specified. | `remove` turns an unpaid debt (1) into a removed one (6). On a removed debt it changes nothing. On a paid debt (8) it gets 400 `A paid debt cannot be removed; delete it instead`. `activate` turns a removed debt into an unpaid one and clears its remove note. On an unpaid or paid debt it changes nothing. |
| `paths./subscription/{subscription_id}.delete` (deleteMembershipDue) | The side effects are not documented. | Deleting a payment also deletes the refund records that share its transaction, and a successful payment leaves the member's `total_financial`. A bank transfer matched to the payment goes back to waiting: `payment_status` 8, unmatched, with no transaction type. Every delete recomputes the member's balances. |

## Debt categories

| Spec location | Problem | Mock behavior |
| ------------- | ------- | ------------- |
| `components.requestBodies.DebtCategoryName` ("unique in the organisation ignoring case") | Whether deleted categories count is not documented. | Only live categories count, so a deleted category's name can be reused. Case is folded under the Turkish locale. A name that is empty after trimming gets 400. |
| `paths./debt-categories.get` ("by name") | The collation is not documented. | Turkish collation, ties by id. `query` matches part of the name, ignoring case and Turkish accents. |
| `paths./debt-categories/{category_id}` GET, PUT and DELETE on a deleted category | Not documented. | 404 `Debt category not found`. |
| `DebtCategoryListItem.update_date` ("Last rename timestamp") | Not documented for API renames and deletes. | A rename sets `update_date` to now with no `updated_by_id`. A delete leaves both alone. |
| `paths./debt-categories/{category_id}.delete` 409 "while another move involving either category is not finished" | Moves run within the request. | A move cannot be left unfinished in the mock, so this 409 never occurs. The 409 `DebtCategoryInUse` comes only from a category in use without a `replacement_id`. The usage counts debts of every state and the category's automations. A `replacement_id` naming the category itself gets 400. An unknown or deleted one gets 404 `Replacement debt category not found`. A query value that is neither empty nor an id gets 400. |
