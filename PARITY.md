# Parity gaps register

The mock's contract is the pinned Fonzip OpenAPI spec, `spec/fonzip-openapi.yaml` (OpenAPI 3.0.3, `info.version` 2.44.0). This register lists every place where the spec is silent or contradicts itself, and what the mock does there. Each entry names its spec location.

Gaps found while implementing a domain go in that domain's folder, so parallel work never edits this file. Write the gap in `src/domains/<domain>/GAPS.md`. If it makes a documented status, input, or property unreachable, add a waiver with the same reason to `src/domains/<domain>/parity-waivers.json`. A domain waiver must list its operations by id, and it can only name operations its domain owns. The waivers in the top-level `parity-waivers.json` cover the foundation and rules that hold for every operation.

## Corrections from production

Where production answers differently from the pinned spec, the mock follows production. `bun run parity:prod --live` is the evidence: it is read-only, it compares production with the spec and with the mock, and it prints no production data. `src/spec/production/` holds the corrections, one file per `parity:prod` area (`auth`, `people`, `templates`, `dues`, `forms`). `normalizeSpec` applies them after the normalizations above and before the generic passes, so the generated types, the route table, the validators, and `parity:prod`'s own spec check all see the corrected spec. The pinned YAML stays as published, so `bun run sync-spec` still works. A correction names its schema by JSON pointer, says what production showed, and can replace the schema, rename, remove, add or require properties, or make them nullable. It must point at the schema itself, never at a `$ref`, so a schema shared by several operations never changes by accident. A pointer that no longer resolves fails at boot.

Each domain's `GAPS.md` lists the corrections for its operations. These hold for every operation:

| Topic             | Production                                                                                         | Mock behavior                                                                                                                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 401 text          | `Unauthorized access`, also in `invalid_client: Unauthorized access` from `/token`                 | Same text. The spec's response is named `Unauthorized Access`.                                                                                                                                                                              |
| 404 texts         | Turkish texts such as `Kullanıcı bulunamadı`                                                       | `PRODUCTION_NOT_FOUND` in `src/api/errors.ts` holds each text production has shown, keyed by subject: user, webhook, template, membership due, debt, debt category, and form. A subject production has not shown keeps `<Thing> not found`. |
| 400 texts         | Some validation failures carry production's own words, for example `values_list parametresi eksik` | `src/api/production-messages.ts` maps each observed failure to production's text. Every other failure keeps `Invalid values: <reason>`.                                                                                                     |
| `GET /me` `phone` | `null` for an association without a phone                                                          | `AssociationInfo.phone` is nullable. The `kelder` association has no phone.                                                                                                                                                                 |

## Data and behavior choices

| Topic                              | Mock behavior                                                                                                                                                                                                                                                                                                                |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Clock                              | `now` starts at 2026-11-01T09:00:00+03:00 on every boot. On the server it then runs in real time. In tests it moves only on `clock.advance`. Seed dates are relative to that start.                                                                                                                                          |
| Dates                              | Date-times are emitted in Europe/Istanbul time with a `+03:00` offset.                                                                                                                                                                                                                                                       |
| Contact data                       | Synthetic. Email addresses use `.example` domains, phones are E.164 mobile numbers, and TC kimlik numbers pass the checksum.                                                                                                                                                                                                 |
| Ids                                | Each collection keeps one counter shared by all organisations, so ids never collide across organisations.                                                                                                                                                                                                                    |
| `GET /me`                          | Served from the organisation's configuration in `src/auth/tenancy.ts`.                                                                                                                                                                                                                                                       |
| Currencies and template categories | Static tables in `src/store/reference.ts`: TRY 1, USD 2, EUR 3, GBP 4.                                                                                                                                                                                                                                                       |
| Tags                               | Names may repeat, because the spec documents no uniqueness rule. Lists come back in id order. `query` matches the tag name case-insensitively under the Turkish locale. A leading `-` excludes matches.
